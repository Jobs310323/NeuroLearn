## 1. Продукт в одном абзаце

NeuroLearn не передаёт знания — он выстраивает прочные нейронные связи через
практику. Пользователь задаёт цель, система строит граф знаний, и дальше вся
работа идёт циклами «извлечение из памяти → обратная связь → рефлексия →
разнесённое во времени повторение». Целевое состояние каждого узла графа —
**автоматизм**: высокая точность при низком времени реакции, устойчивая
на отложенных проверках.

## 2. Антицели

Явно **не** делаем:

- Видеокурсы и длинные лекции. Теория — минимальное ядро между практиками.
- Очки, бейджи, «стрики ради стриков». Метрика мастерства — `time_to_mastery`
  и `knowledge_strength`, а не накопленные баллы.
- ИИ, который решает за пользователя. Тьютор возвращает вопросы; модуль
  проверки проектов задаёт вопросы по коду, а не пишет код.
- Ленты, соцфичи, рейтинги других пользователей.
- Оценка «прошёл/не прошёл» как конечная цель. Конечная цель — перенос
  навыка в новый контекст.

## 3. Научные основы (закреплено, менять только с обоснованием)

Полные ссылки — в `src/lib/science/citations.ts`. Ключ в скобках = `CitationKey`,
он же значение `content_blocks.science_citation_key` и проп компонента
`<ScienceHint citation="..." />`.

| # | Принцип | Инженерная реализация |
|---|---------|----------------------|
| 1 | **Активное припоминание** (`testing_effect`, `pretesting`) — Roediger & Karpicke, 2006; Richland, Kornell & Kao, 2009 | Первый блок каждого узла — `pre_assessment` (флаг `content_blocks.pre_assessment`, `assessments.is_pre_assessment`). Переход к теории закрыт до попытки ответа. Ошибка на pre-тесте — ожидаемый и полезный исход, UI формулирует её как «зона роста», не как провал. |
| 2 | **Интервальное повторение** (`spacing_effect`, `fsrs`) — Cepeda et al., 2006; FSRS | Библиотека `ts-fsrs`. **Собственный SM-2 не пишем.** Состояние в `fsrs_cards` (поля 1:1 с типом `Card`), журнал в `review_logs` (1:1 с `ReviewLog`) — нужен для `rollback` и будущей оптимизации весов на личных данных. Единица планирования — узел. |
| 3 | **Интерливинг** (`interleaving`) — Rohrer, 2012 | `GET /api/practice/next?mix=true` собирает вопросы из узла-якоря + смежных узлов по рёбрам `related`/`contrast`/`analogous` из `node_edges`. Доля смеси — `SessionConfig.interleaveRatio`, стартует от `cognitive_profile.interleavingTolerance`. |
| 4 | **Эффект генерации** (`generation_effect`) — Slamecka & Graf, 1978 | Агент `Tutor` работает только через инструмент `SocraticMethod`. Прямой ответ запрещён на уровне системного промпта **и** проверяется гвардом `assertNoDirectAnswer` перед стримингом. Есть аварийный выход: после 3 неудачных сократических циклов тьютор даёт разбор — иначе фрустрация. |
| 5 | **Метакогниция** (`metacognition`, `calibration`) — Flavell, 1979; Dunlosky & Rawson, 2012 | Таблица `reflections`. Узел не переходит в `mastered` без записи типа `post_module`. Уверенность (`user_responses.confidence_level`, 1–5) собирается **до** показа результата; разрыв «уверенность − точность» пишется в `node_progress.calibration_gap` и триггерит `MetacognitiveCoach`. |
| 6 | **Обратная связь с задержкой** (`delayed_feedback`) — Shute, 2008 | `assessments.feedback_mode`: `recall`/`understand` → `instant`, `apply` и выше → `delayed`. Флаги `instant_feedback`/`delayed_feedback` из ТЗ сохранены и защищены CHECK-констрейнтом на взаимоисключение. При `delayed` сервер не отдаёт правильность до `POST /sessions/:id/complete`. |
| 7 | **Вариативность практики** (`variability_of_practice`) — Schmidt, 1975 | `ContentGenerator` создаёт 3–5 формулировок одного навыка в разных контекстах, объединённых `assessments.variant_group_id` + `context_label`. Движок практики никогда не берёт два варианта одной группы в одну сессию. |
| 8 | **Желательные трудности** (`desirable_difficulties`) — Bjork & Bjork, 2011 | Интерливинг, отложенная проверка и растущие интервалы включены по умолчанию. UI заранее предупреждает: «на тренировке будет тяжелее — это ожидаемо», чтобы просадка не читалась как регресс. |
| 9 | **Разобранные примеры** (`worked_examples`) — Sweller & Cooper, 1985 | Блок 4 = `worked_example`; подсказки в блоке 6 (`guided_practice`) затухают от сессии к сессии (fading). `user_responses.hints_used` отслеживает зависимость от подсказок. |
| 10 | **Автоматизм** (`automaticity`) — Shiffrin & Schneider, 1977 | Статус `automated` требует точности **и** скорости. Формула — в разделе 5. Геймификация построена на `time_to_mastery_seconds`, а не на очках. |

## 4. Роли пользователя и основные сценарии

**Пользователь один** — самостоятельно обучающийся взрослый. Ролей и
преподавателей нет.

Сценарии:

1. **Постановка цели.** Вводит цель → `ContentGenerator` строит дерево знаний
   (узлы + рёбра prerequisite/related) → пользователь правит его на карте.
2. **Диагностика.** Прогон `pre_assessment` по корневым узлам: система сразу
   красит граф — что уже известно, где пробелы.
3. **Изучение узла.** 10 блоков от pre-теста до рефлексии.
4. **Ежедневная практика.** Очередь повторений FSRS + интерливинг-микс.
5. **Разбор с тьютором.** Сократический диалог по конкретному узлу.
6. **Рефлексия.** Дневник после модуля, разбор ошибок, недельный обзор.
7. **Проект и защита.** Артефакт + вопросы ИИ по нему → вскрытые пробелы
   возвращаются в граф как `has_gaps` и во внеочередное повторение.

## 5. Ключевые метрики и формулы

### `knowledge_strength` (0–100)

Композит четырёх компонент, хранится в `node_progress.knowledge_strength`:

```
strength = 100 × (0.35·R + 0.30·A + 0.20·S + 0.15·C)

R = retrievability   — вероятность вспомнить сейчас, из ts-fsrs по карточке узла
A = accuracy         — точность на последних N=20 ответах (взвешенная по свежести)
S = speed            — clamp(targetResponseMs / medianResponseTimeMs, 0, 1)
C = coverage         — доля пройденных уровней Блума среди заданных для узла
```

### `automaticity_index` (0..1)

Доля верных ответов, уложившихся в персональный порог скорости:

```
threshold = min(assessment.target_response_ms, 1.3 × personalBaseline(cognitiveLevel))
index     = correctAndFast / correctTotal   (по последним 20 ответам)
```

### Переходы статусов узла

| Из | В | Условие |
|----|---|---------|
| `not_started` | `in_progress` | зафиксирован первый ответ на `pre_assessment` |
| `in_progress` | `has_gaps` | точность < 0.5 на ≥ 6 ответах, либо пробел вскрыт защитой проекта |
| `in_progress` | `mastered` | `knowledge_strength ≥ 80` **и** есть рефлексия `post_module` **и** ≥ 2 сессии в разные календарные дни |
| `mastered` | `automated` | `automaticity_index ≥ 0.8` **и** ≥ 3 успешных повторения FSRS с интервалом ≥ 7 дней **и** точность ≥ 0.9 в интерливинг-режиме |
| `mastered` / `automated` | `needs_review` | `fsrs_cards.due ≤ now()` |

Требование «в разные календарные дни» — прямое следствие принципа 2:
мастерство не выдаётся за один заход.

### `time_to_mastery_seconds`

Сумма `practice_sessions.duration_ms` по узлу от `first_studied_at` до
`automated_at`. Это единственная метрика, которую UI показывает как «рекорд» —
и сравнивается она только с собственной историей пользователя.

## 6. Структура модуля: 10 блоков

Порядок фиксирован (`content_block_type`), `ContentGenerator` обязан выдать все 10:

| # | Тип | Назначение | Принцип |
|---|-----|-----------|---------|
| 1 | `pre_assessment` | Тест до теории | `testing_effect`, `pretesting` |
| 2 | `activation` | Связь с уже известным | `generation_effect` |
| 3 | `concept` | Минимальное ядро теории | — |
| 4 | `worked_example` | Разобранный пример с рассуждением | `worked_examples` |
| 5 | `contrast_cases` | 3–5 контекстов + контрпример | `variability_of_practice` |

| 8 | `interleaved_practice` | Смесь со смежными узлами | `interleaving` |

## 7. Архитектура агентов

Четыре системных промпта. **Прямых вызовов друг друга нет** — обмен только
через таблицу `user_context` (slot = `user_id + agent + scope + path_id + node_id`,
оптимистическая блокировка по `version`).

| Агент | Вход | Выход | Инструменты |
|-------|------|-------|-------------|
| `ContentGenerator` | цель пути, срез графа, `gaps` из контекста | дерево узлов / 10 блоков / банк заданий | `EmitNodes`, `EmitBlocks`, `EmitAssessments` |
| `Tutor` | сообщение, узел, история, контекст | стрим наводящих вопросов | `SocraticMethod`, `LookupNode`, `LogGap` |
| `ProgressAnalyzer` | `user_responses`, `fsrs_cards`, `node_progress` | обновление `cognitive_profile`, статусов, `facts.gaps` | `UpdateProfile`, `FlagGap`, `RecommendFocus` |
| `MetacognitiveCoach` | `reflections`, `calibration_gap` | вопросы для дневника, разбор калибровки | `AskReflection`, `ReportCalibration` |

Жёсткие правила:

- Любой структурный ответ LLM валидируется Zod перед записью в БД.
  Провал → `ai_generations.status = 'schema_failed'`, одна повторная попытка
  с текстом ошибки, затем отказ. Невалидированные данные в БД не попадают.
- `Tutor` не имеет доступа к таблице `assessments.correct_answer`.
- Каждый вызов пишется в `ai_generations` (модель, версия промпта, токены,
  стоимость, латентность).

## 8. UX-принципы

- Стиль Linear/Cursor: минимализм, плотная сетка, клавиатура-first,
  командная палитра (`Cmd+K`).
- Мгновенная отзывчивость: скелетоны на серверных границах, оптимистичный UI
  на ответах и оценках FSRS с откатом при ошибке.
- **Карта знаний** (React Flow): зум, цветовое кодирование статусов,
  пунктирные рёбра prerequisite, свечение у узлов с наступившим повторением.
- **Всегда видимый виджет**: прогресс пути + очередь ближайших повторений.
- **`<ScienceHint>`** — иконка рядом с каждой нестандартной механикой
  (тест до теории, перемешанная практика, скрытый результат): тултип
  «Почему мы так делаем?» → правило продукта, вывод исследования, ссылка.
- Цветовая семантика статусов: `not_started` — нейтральный серый,
  `in_progress` — синий, `has_gaps` — янтарный (не красный: пробел это не
  провал), `mastered` — зелёный, `automated` — зелёный с обводкой,
  `needs_review` — фиолетовый пульс.
- Доступность: контраст WCAG AA, статус дублируется формой/иконкой, а не
  только цветом, `prefers-reduced-motion` уважается.

## 10. Технические решения и их обоснование

- **Единица FSRS — узел, а не отдельный вопрос.** Повторение узла = короткий
  смешанный набор его заданий с разными `variant_group_id`. Это делает
  повторение проверкой навыка, а не заучиванием конкретной формулировки,
  и сохраняет очередь обозримой.
- **`node_edges` вместо отдельной таблицы prerequisites.** Одно ребро с типом
  обслуживает и блокировку по зависимостям, и подбор пула для интерливинга.
- **Дерево (`parent_id`) и граф (`node_edges`) разделены.** Первое — навигация
  и раскладка, второе — семантика зависимостей. Слияние их даёт циклы в UI.
- **Флаги `instant_feedback`/`delayed_feedback` продублированы рядом с
  `feedback_mode`** — так требует ТЗ; целостность держат CHECK-констрейнты,
  рассинхрон невозможен на уровне БД.
- **Изоляция данных — в коде, не в RLS.** База на Neon, клиент в неё не ходит:
  все запросы идут через Server Actions и Route Handlers, `userId` берётся
  только из сессии, владение проверяется по цепочке до `learning_paths.user_id`.
- **Импортированные материалы — основа генерации.** Конспекты, книги и PDF
  разбираются в текст (`source_documents` / `source_chunks`), оригиналы не
  хранятся. Сгенерированный узел ссылается на конкретные фрагменты через
  `node_sources` — видно, на чём основан материал.
- **Хранение векторов не вводим.** Поиск по источникам полнотекстовый
  (GIN по `to_tsvector`): бесплатно, без embedding-API, на личных объёмах
  достаточно.
- **Модели — сначала бесплатные.** Провайдер и идентификаторы моделей заданы
  переменными окружения; переход на платные (OpenRouter, Anthropic) — смена
  значения, без правок кода.

## 11. Языковая политика (решено)

Основной язык интерфейса и контента — **русский**. Английский используется
там, где перевод вредит точности:

- общепринятые технические термины и названия технологий сохраняются в
  оригинале (`Server Action`, `hook`, `middleware`, `interleaving`);
- имена сущностей кода, БД, API — только английские;
- названия исследований и авторы — в оригинале;
- если у термина есть устоявшийся русский эквивалент — используем его
  («узел знаний», «повторение», «обратная связь»).

`UserPreferences.locale` остаётся в схеме (`'ru' | 'en'`), но переключатель
языка в UI Этапов 1–4 не делается: значение по умолчанию `'ru'`, поле —
задел на будущее. Промпты агентов задают выход на русском с сохранением
англоязычной терминологии.
